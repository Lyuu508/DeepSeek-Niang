# v0.0.9 人格回收站与 schema 10

打开「人格管理 → 操作 → 移入回收站」，确认后隐藏对应人格。当前使用的人格会切换到可用人格。默认人格和最后一个可用人格由数据库业务层保护。回收站保留原始人格 ID、聊天、关系、记忆、设置与生活记录。后台任务暂停并撤销租约，已启动的主动请求保留不确定状态。恢复后可以继续使用原人格、切换回聊天并按需继续已暂停的任务。

「永久删除」和「清空回收站」需要在各自弹窗内确认。确认绑定到当时显示的回收站决定 ID，过期操作会提示重新核对。清空以一笔事务处理选中的回收站快照。任一数据库操作失败会回滚整批，避免界面不清楚哪些人格被清理。

## 同步规则

schema 10 将状态决定作为经现有设备认证和签名传播的数据。人格资料仍用原来的合并规则。两个设备的回收站决定以 Lamport 时钟、设备 ID、事件 ID 排序，状态和时间一起生效。永久删除为终态，优先于普通恢复。配对与密钥存储沿用现有数据。两端升级至 v0.0.9 后可继续原配对的同步。

删除事务清理关联的 SQLite 业务记录、FTS、插件人格配置、提醒、任务和本机媒体索引。签名同步历史保留序号与原事件摘要，供对端识别重播。已经删除的历史快照由原设备重新签发摘要占位内容。离线设备提交的过期记录会推进检查点，原内容不会重新投影。回收站显示本机、待确认、已确认或已从对端同步。离线设备在下次成功同步前可保留自己的旧副本。

旧备份和原媒体文件独立保留。SQLite 删除之外的文件系统残留取决于介质与系统。使用已独立保存的备份恢复旧数据前，应了解同步可能再次应用已确认的删除。

## 数据迁移

迁移 0001–0009 原样保留。0010 增加生命周期、删除身份和签名占位队列，以及设备本地插件数据表。字号复用设备设置表。旧聊天样式自动读取为标准模式。

打开旧库时先在私有目录生成包含已提交 WAL 的一致性备份，再进行 SQLite 事务迁移。检查已有表的记录计数、外键和 SQLite quick_check 后提交。双端测试包含相同 ID 的恢复、重复传输、离线修改与永久删除冲突、历史内容清理及批量回滚。合成数据的回环 mTLS 使用 Windows 和 Android 实体身份标签，家庭网络和实际手机仍需验收。
