# 阶段 1 明确验收标准

这是一份双端验收合同。阶段 1 已实现源码和可用环境测试，但两端原生安装运行与真实 API 均未通过；两端都完成才能称为阶段 1 完成。

| 编号 | 操作 | 必须观察到的实际结果 |
|---|---|---|
| P1-01 | Windows 10/11 x64 构建、安装、启动 | 原生 Tauri 窗口打开，SQLite 位于应用数据目录；保存/删除存储验证有效 |
| P1-02 | Android API 29+ ARM64 构建 APK、安装、启动 | 原生 WebView/插件正常，SQLite 为 app 私有文件；横竖屏/小屏可用 |
| P1-03 | 每端单独输入用户自己的 DeepSeek Key | set/replace/delete/has 正常；Key 不进入业务 DB、日志、前端缓存、构建产物 |
| P1-04 | 两端分别发送真实问题 | 官方 API 返回真实内容；保存模型/请求/用量记录；不能用夹具回复通过 |
| P1-05 | 流式输出中点击停止 | 可见生成尽快停止，HTTP 取消，保存 interrupted 变体；迟到 token 不继续写入 |
| P1-06 | 重新生成 | 新 generation/assistant 变体形成，同一用户消息不重复，原变体可追溯 |
| P1-07 | 多轮聊天、关闭重开 | 最近对话连续，历史分页正确；当前分支上下文与单端记录一致 |
| P1-08 | 流式中杀进程后重启 | SQLite 完整、无半事务；草稿恢复为 interrupted，不自动重复收费 |
| P1-09 | 模拟无网络、超时、401、429、余额不足 | 有可理解错误与有限退避；401/余额不足不无限重试；输入不丢 |
| P1-10 | 比较两端相同人格版本 | 基础性格、称呼与边界一致，不要求模型随机输出逐字相同 |
| P1-11 | 查看发送范围、排除记忆 | 请求只包含允许的上下文；日志不记录正文/认证头；关闭在线 embedding |
| P1-12 | 删除 Key 后再次生成 | 显示未配置密钥，不回退到硬编码 Key；另一端 Key 不受影响 |
| P1-13 | 不启用桌宠/视频/NAS | 两端仍能独立完成聊天；这些后期模块不作为前置依赖 |

真实 API 测试前由用户在设备上的安全设置页输入 Key，不在聊天中索要、不要求提交到 .env 或 Git。
纯文本聊天允许内容离开本机交由 DeepSeek 处理，应展示提供商和本次可发送范围。没有云端聊天数据库。
Windows 证书/SmartScreen 与 APK 签名状态必须如实说明；阶段 1 可使用本地开发签名包验收，不能称为已公开正式发布。
Android 后台、设备发现、数据同步为阶段 2；阶段 1 不承诺强制停止后联网、不承诺手机和电脑已经共享历史。

结果记录至少包含：OS/系统版本、设备架构、安装包 SHA-256、工具链/SDK、用例编号、实际观察与失败日志摘要。
API 流解析和错误分支可用明确标记的 fixture 做自动测试；真实供应商连通性和计费只能用实际请求验证，两者分列。
