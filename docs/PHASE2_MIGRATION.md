# v4 局域网同步迁移与恢复

仅新增 `0004_lan_sync.sql`，v1～v3 迁移字节保持不变。运行时检查所有迁移哈希和 user_version，高版本库拒绝写入。
旧 v1/v2/v3 文件在同一目录生成 SQLite Online Backup `*.pre-v4-UUID.bak` 后，所有未执行 DDL 在一个 Immediate 事务内完成。备份失败不开始迁移，DDL/外键/行数检查失败则整体回滚。表重建按 SQLite 官方流程在尚未交给应用的独占连接上临时关闭 FK 动作，提交前显式检查全部外键与原行数，提交后恢复 FK 强制执行；不会将关闭约束的连接交给业务层。成功后 user_version=4；再次打开不重做迁移备份。

新增生产事件日志、事务待发队列、逻辑字段寄存器、冲突修订、永久删除标记、可信设备公开绑定与导入档案授权。首次启用签名队列时按依赖顺序快照原有数据，再接续捕获本地写入；旧 v1 sync_events 信封、序号、消息 UUID 和人格归属不重写。五张原型表的自然键增加 persona_id，原来未指定人格的原型记录明确归到该档案的默认人格；旧任务的检查点等子记录保留。生产协议不调用 lab 导入。

两端凭据仍以各自本机原 profile/应用身份保存，私钥另用独立系统安全存储槽。远端档案和人格保留原 UUID；`lan_profiles` 显式记录人工配对后的共享档案，选择人格仍是本机设置。不会用空档案覆盖已有聊天或重建已有默认人格。

待发队列与业务写入在同一 SQLite 事务，签名/分配新协议序号/移除待发项也在事务中。接收端在完整批次通过认证、签名、顺序、类型、依赖、所有权与完整性检查后提交，提交后才 ACK。签名失败、序号缺口或存储错误不提前推进游标。字节上限与事件条数同时限制分页。
消息不可变并集；记忆与配置按字段逻辑版本稳定选主，保存异值修订；墓碑在晚到 put 之前也生效，删除内容从正常物化表和 FTS 隐藏。旧原始日志、冲突历史和备份仍可能保留正文，这是逻辑删除，不是彻底擦除。

恢复旧备份前关闭应用和同步，先另存当前库及已提交 WAL 的一致备份，再在授权的设备私有目录恢复，并检查 integrity_check/foreign_key_check/user_version。不要修改 user_version 欺骗旧版，不删除库或卸载应用解决问题。恢复历史库后须人工重新核对配对/签名事件流，不回退游标冒用已发序号；没有自动跨设备历史回滚功能。
