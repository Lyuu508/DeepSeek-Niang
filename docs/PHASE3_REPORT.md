## 数据与双端一致性

当前 schema 6，新建两份增量迁移，原 0001～0004 原样保留。升级前 Online Backup、一个事务、外键/行数校验、失败回滚测试。新关系证据/情绪/记忆元数据/候选/设置/主机/生活事件/主动台账通过已签名事件同步；本机 worker 状态与处理游标不复制。数据库约束及接收验证核对来源消息、人格、源设备与主机，真实 TLS 测试还拒绝“签名正确但内容证据伪造”的关系事件。已配对旧版本不得混用 schema 4/6，两端都升级。

默认人格映射保留旧行及原消息 ID，主人真正创建的多个人格各自隔离。[详细缺陷报告](PHASE2_PERSONA_IDENTITY_FIX.md)。没有实际用户数据库，不能承诺已经扫描或修复主人设备。

## 签名与数据保护

本次已对真实 v0.0.1 与现有 v0.0.2 APK 执行官方 apksigner，证书分别为：

- 原正式：`9de96ea5fb1d0b3f91ea73d9a16c030428453b15838927a85f86773eaef208a1`。
- 当前 test2：`fefb57342751c7bd5ef8271e4a8b09f8702c0285e0120e8407b557d20dbbf153`。

二者不同，本版保留 `io.local.deepseekcompanion.test2`、显示名“DeepSeek娘 扫码测试版”和后者证书，复用 GitHub `TEST_RELEASE_SIGNING_B64` 及已保存兼容单项配置，不生成替代签名。本连接 Secrets 元数据为 HTTP403，不能据此判断缺失；CI 只输出存在布尔值，签名任务实际恢复私钥、keytool 证明确可读，并用旧 APK 对比。最终新 APK 的官方报告才证明本版签署成功。Windows 沿用 `069f0150a9698a8178bdaf7dfea13f5509185aa69b9ba940f5473edbafa8af62` 自签名测试证书，不能冒充公共 CA 或保证消除 SmartScreen。

test2v2 → v3：同 ID、同签名、1003 > 1002，升级原私有数据并先备份，真实手机覆盖仍待验收。正式 v1 / 早期 .test → test2：独立安装不触碰旧数据；保留旧应用和未同步消息，已有同步到电脑的数据可由同一电脑再同步。完整跨身份导入尚未实现，不能说新包能读取旧私有目录；需原应用受控导出或原签名升级配合，再进行保留 ID、去重、可回滚的导入，主人确认前不移动旧库。禁止卸载旧版/清数据来解决签名问题。
