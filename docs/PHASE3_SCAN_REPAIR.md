# 阶段 3 追加：扫码连接与人格重复修复

基线为已公开 v0.0.3 / main `e53b5971cb215d295438aed0d55be5eb8be9a16b`。本次是阶段 3 修复，候选版本 0.0.4 / Android1004；不开发阶段 4。未取得主人真实手机数据库或网络，不能声称已查到其实际重复条数，不能将回环测试当成家庭网络验收。

## 可复现根因

旧 v0.0.2/schema4 已签名待发事件中，`personas` 没有后来 schema5 新增的 `avatar_resource`，`api_usage_records` 没有 schema6 新增的 `purpose`。v3 导入器要求事件行与当前表列完全一致，升级后发送历史事件会得到 `invalid input: unknown sync field`，整批事务拒绝。认证后的默认人格归一也依赖该批数据，因此只建成设备信任，无法完成首次同步，自动默认项仍重复。新建数据库的测试没有旧队列，未覆盖这一升级情形。本次先用真实 TLS + 旧签名行复现失败，再修复并通过同一用例。前后证据在 [验证目录](validation-phase3-followup/README.md)。

另一个状态错误：Windows 在手机已主动完成双向交换后，尝试通过发现服务反向拨号手机；手机没有公布可用地址时，失败结果覆盖刚成功的状态。现在 QR 连接采用手机发起的双向交换，Windows 不因缺少反向地址覆盖成功状态。它不绕过防火墙，也不承诺路由器隔离网络能够连接。

## 修改与安全边界

- `companion-core/replication.rs` 只为上述两项已知新增列在投影视图补齐固定默认值。原始签名、消息/事件 ID、日志及哈希完全不改，不重新签署历史；其他缺列、多列、身份/签名错误仍拒绝。
- `companion-sync` 保存并优先使用成功地址，私有网卡地址按本机子网匹配排序；先验证全部地址再联网，不扫描网段。首次扫码在返回成功前实际完成同步；后台 tick 与扫码串行，数据错误不再吞为网络错误。
- Windows 权威人格、不可变自动默认别名沿用 v3 设计。已认证连接导入成功后，手机采用电脑默认人格的原 ID、名称、头像、人设、模型/聊天设置；旧聊天/记忆在同一 canonical 范围聚合，不删除旧原行，不改变消息 ID，不合并主人手动创建的同名人格。重复扫描不新增人格。
- API Key 按主人本次明确授权单独一次传递。二维码只含短期高熵配对信息和公开连接资料；Key 不进入 QR、SQLite、同步日志、状态 JSON 或普通同步。第二次 TLS1.3 连接必须具备已可信手机证书、同一 QR 的令牌/会话/设备、未过期且已提交的电脑授权。手机写入自身系统安全存储并读回验证，界面仅显示配置状态。明确重新扫码会用电脑配置更新手机已有 Key；电脑未配置时保留手机已有配置。安全存储失败仍继续聊天/人格同步，并显示 Key 配置失败。
- 撤销连接阻止后续同步，但不能使已复制的 API Key 在提供商失效。如需撤销使用权，应在手机设置中删除并在 DeepSeek 平台轮换 Key。只给自己的可信手机展示二维码。

## 数据迁移与覆盖范围

新增 schema7 只有可重建的本机全文索引及触发器，0001～0006 字节保持不变。打开旧库前通过 SQLite Online Backup 保存 `.pre-v7-UUID.bak`（含 WAL 一致状态）；迁移在事务内验证行数、完整性和外键，失败回滚。真实 SQLite 合成 v6 文件测试覆盖备份、历史索引回填和注入失败回滚。迁移成功后有新聊天时，不可直接用旧备份覆盖；先停止应用并保留当前库/备份，人工比对恢复，不要求主人卸载或清数据。

已存在的自动默认重复记录采用 v3 可审计别名，原行保留；没有证据证明属于自动默认的记录不会自动修复。无法从云环境直接检查或迁移主人手机上的实际数据库。

## 自动化及待验收

实际回环 TLS 用例覆盖：旧队列升级、相同 persona_id/名称/头像/System Prompt、记忆/关系/情绪、两方向消息、重复扫码、离线补传与主机重启、原消息 ID 保留、手动同名人格保留、无反向发现的手机拉取。新增 Key 用例覆盖正确传递、普通同步不传、显式重扫更新、匿名/错误证书/令牌/过期/撤销拒绝、两端存储失败和电脑无 Key。

Rust 与 SQLite 测试使用真实数据库和加密套接字；API Key 测试为无效合成字符串及隔离存储，不能视为 Windows Credential Manager 或 Android Keystore 真机验收。家庭 Wi-Fi、Windows 专用网络防火墙、相机扫码、实际安全存储及覆盖安装按 [清单](PHASE3_FOLLOWUP_ACCEPTANCE.md) 验收。
