# 局域网协议与任务所有权设计

## 实现边界

阶段 0 实现了**单进程内两个独立 SQLite 副本的事件合并实验**。
没有 mDNS/NSD、二维码、TLS、真实 socket 或网络签名验证。`lab` 方法不得作为公开同步 API。
阶段 2 先完成下述安全封装与版本化事件 DTO，再开放任何端口。同步不共享 SQLite 文件，不提供远程 SQL。

## 1. 身份、档案与首次数据归属

- `profile_id` 表示同一个角色/用户数据集；`device_id` 是该数据集的一条持久复制身份，UUID 随机生成。
- 每个身份拥有独立私钥，保存在系统安全存储；广播名称和 IP 均不作为身份凭据。
- 新空客户端在配对后加入对方的 `profile_id`，再从零检查点引导；不能保持两个随机档案 ID 却声称已经同步同一人物。
- 如果两端已有独立数据，首配向导必须展示来源与数量，让用户选定共同角色档案。先独立备份，再将另一档案作为导入批次合入。
- 导入创建新复制身份/事件流，保留消息/记忆的实体 ID与原始来源引用，使用 `import_batch_id + source_event_id` 唯一映射去重；旧签名事件保留为档案，不修改签名正文后冒充原事件。
- 对同一实体 ID 内容不一致的初始导入必须展示冲突并产生新的修订或新实体；关系依据按源证据去重，不能导入总分相加。
- 阶段 0 `Store` 只支持单活动档案，上述首配迁移属于阶段 2 必测功能；不得直接重写旧 DB 的 profile 字段或复用有缺口的旧序号流。

## 2. 发现与网络条件

服务类型 `_dscompanion._tcp.local.`；TXT 仅放协议版本、随机公开实例 ID、功能位与监听端口。
不用设备昵称、聊天片段或长期 token 作为广播内容。发现结果都是不可信地址候选。

Windows 用 mDNS responder/browse；Android 用 NsdManager 与生命周期绑定。Android 前台维护会话，网络切换后重新绑定有效接口。
阶段 2 必须处理 Android 17 / target SDK 37 的 `ACCESS_LOCAL_NETWORK`，根据系统/target 判断权限，拒绝时说明并保留离线能力。
NSD 系统选择器的权限豁免不是任意 IP 直连的豁免；手动 IP 和自动重连都须分别验证。
来源：[Android 官方局域网权限](https://developer.android.com/privacy-and-security/local-network-permission)。

设备发现失败提供 IP + 端口输入，不扫描整个网段。IP 只作为地址；认证仍必须通过原配对身份。
Windows 仅按用户允许配置“专用网络”应用防火墙例外，不关闭防火墙、不自动映射公网端口。
局域网中必须 IP 可互达；有线/Wi-Fi 混合不影响协议。不同子网可能 mDNS 不通但 IP 可通；访客 Wi-Fi/AP 隔离可能都不通。

## 3. 二维码配对流程

1. A 在用户打开“添加设备”后生成 CSPRNG 256 位单次 token、随机 session ID，过期 120 秒，最多 5 次失败尝试。
2. 二维码包含版本、会话、公钥/证书 SHA-256 指纹和地址候选。token 不进日志、不广播、不进入普通业务表；退出配对页即撤销。
3. B 扫码后仅连接所选私有地址，先固定并验证 A 的证书指纹，再发送 token；不先通过不可信 TLS 泄露 token。
4. 首次连接为固定服务端身份的 TLS 引导通道；B 生成本机身份并证明私钥持有能力。A、B 均展示对方身份摘要，由用户完成首配确认。
5. 双方保存公钥绑定与档案加入授权，销毁 token。后续仅允许已配对身份的双向 TLS，忽略陌生客户端。
6. 手动回退保留二维码/完整高熵一次性码与指纹核对。不能把六位 PIN 的哈希当成安全通道；若以后加入短 PIN，必须使用经审查的标准 PAKE 实现并验证身份绑定。

TLS 1.3 由 rustls 等成熟实现提供，不自行实现握手、密码套件或 key derivation。配对协议本身还要做恶意中间人、重放、过期和错误指纹测试。
API Key 不因信任设备建立而复制；每台执行模型任务的设备单独配置凭据。

## 4. 事件格式

阶段 0 实验事件字段：

| 字段 | 含义 |
|---|---|
| schema_version | 当前实验为 1，未来生产 wire protocol 单独版本 |
| profile_id | 同一数据集 |
| event_id | UUID v4，全局去重 |
| origin_device_id / origin_seq | 原始设备及本机事务内递增序号 |
| lamport | 已见逻辑时钟的最大值之后递增；不以墙钟排序 |
| entity / entity_id / operation | 类型、对象、put/delete |
| payload | 有类型、有上限的正文；删除为 null |
| checksum | 固定元组 JSON 的 SHA-256，仅完整性实验 |

生产事件还要增加 protocol/schema/rule version、原始签名、密钥 epoch、可选因果依赖和正文哈希。
签名序列化采用标准规范化格式（如 RFC 8785/JCS），不能直接把当前实验 JSON checksum 当作认证。
持久原始签名支持未来 NAS 转发事件时验证真正来源；mTLS 只验证当前连接对端，不能代替原始来源验证。
UUID 不编码壁钟，逻辑数值限制在跨语言安全整数范围。签名、档案、来源成员身份、撤销状态、序列合法性均先于 apply。

## 5. 本地写入与双向增量交换

本地 SQLite `BEGIN IMMEDIATE` 内原子完成：

1. 验证命令与实体类型。
2. 递增本设备序号和 Lamport 值，分配事件 ID。
3. 插入事件、更新物化业务表/索引/墓碑和连续检查点。
4. commit 后通知界面并允许向对方发送。

会话流程：认证 → 协商最低兼容版本、档案/epoch/能力 → 交换 per-origin 连续检查点 → 双向分页发送缺失事件 → 收方验证并事务提交 → 提交后 ACK → 循环直至收敛。
阶段 0 单批最多 256 个事件、单 payload 64 KiB；传输阶段还需压缩前/后总字节上限、解析深度限制和附件独立分块校验。
大视频原文件默认不随业务同步；只同步来源、分析结果与记忆。用户主动传输媒体时独立授权和预算。
接收端可先保存 seq=3，但连续检查点仍停在 0，直到 1、2 都到达才推进。连接断开重传已 commit 批次不会重复插入。
对方的 ACK 仅用于发送优化，不能删除本机唯一副本；已配对设备的离线情况必须参与保留/压缩策略。

**重放检测：** event_id 或 `(origin,seq)` 相同而正文不同，整批拒绝并给出 `EVENT_EQUIVOCATION`，不静默覆盖。
**时钟处理：** 导入更新本机已见最大 Lamport；下次本地写入再加 1。远端墙钟只用于展示和经验证的冷却，不裁决冲突。
**依赖处理：** 后续关系/视频多表事件有引用依赖；需 inbox 待应用队列，全部依赖满足或同一聚合事务完成后才确认应用检查点。
阶段 0 的 message/memory 无跨聚合依赖，因此不应推广为“全部实体同步已完成”。

## 6. 不同数据的合并规则

| 数据 | 合并原则 |
|---|---|
| 聊天消息 | 不可变实体取并集；排序为 Lamport、origin、UUID；保留 reply_to 分支和重新生成变体；删除墓碑隐藏内容 |
| 记忆 | 字段/实体修订按逻辑版本元组裁决；保存失去主版本的修订供审阅；原 ID 永久 delete-wins |
| 关系 | 原始证据事件集合去重，按版本化规则重放；分数和阶段是派生缓存，不跨端相加 |
| 基础人格/共享设置 | 版本化配置；并发不同改动提示，稳定选主保留修订；本机设置不参与 |
| 兴趣 | 合并内容评价与来源证据，再重算权重，不相加设备总分 |
| 生活计划 | 版本化计划修订；发生键防重复；不可变生活事件取并集 |
| 主动消息 | 同一证据目的的 trigger_key 唯一；共享生成候选，投递按设备记录 |
| 视频结果 | source fingerprint + analysis_version + segment range 唯一；合并证据与覆盖，不取最大百分比 |
| 当前活动 | 只接受活动对应合法租约及较新 fence 的检查点；执行设备心跳验证 freshness |
| 任务租约 | 不按 LWW 合并两端“我拥有任务”的字段；以固定协调节点的租约台账为准 |
| FTS/向量/关系快照 | 本地可重建缓存；同步正文和原始事件 |
| API Key / 私钥 / Cookie | 永不进入同步；机器路径、电量和通知权限也只保存在本机 |

## 7. 删除、历史清理与数据恢复

删除为不可变 tombstone 事件，并在一个事务中清理物化正文与 FTS/向量。迟到的旧 put 和并发 edit 不能复活该 ID。
用户撤销删除时创建新 ID并引用原 ID，不能删除墓碑。冲突修订只在明确的历史界面显示，不进入正常检索或 prompt。
阶段 0 保留旧事件正文，因此是逻辑删除。阶段 2/隐私阶段清理需分离保留的 hash/签名头与可擦除正文，推进快照 epoch。
离线过久或被撤销设备不能用旧快照重新注入被清理内容，必须重新配对/引导。历史备份的保留或销毁由用户设置。
崩溃恢复依赖 SQLite 事务与检查点；完整性失败时进入只读诊断/恢复模式，不把损坏副本向另一端复制。

## 8. 任务租约、失败和 NAS 交接

每个共享任务属于固定 `authority_device_id + authority_epoch`；创建时按能力政策选定，不能两端各自以“电脑优先”自行抢同一任务。
协调节点 SQLite 事务检查状态和次数后签发 `(task_id, worker_id, authority_epoch, boot_id, fence, lease_deadline)`。
fence 每次重新领取、暂停、取消、失效或重启都递增；checkpoint/完成提交验证 worker、epoch、boot、fence、有效期和任务状态。
期限由协调端单调时钟判断，不能接受 worker 自报当前时间。worker 按较短本地 deadline 停止新步骤，定期续租。
协调进程重启产生新 boot_id，所有运行中旧租约变为 uncertain，不能沿用进程前的 monotonic tick。

状态：`queued → running → completed`；可 pause/resume/cancel；失败受 max_attempts 和退避限制。
到期/断线/外部请求超时可能出现“API 已执行但结果未收回”，进入 `uncertain`。先查询 provider request、核对已保存结果/checkpoint/预算预留，再决定安全重试。
`request_key = task_id + step_key + input_hash + model_config_version` 保持应用幂等；只有供应商确实支持幂等语义时才可承诺远端防重复。
旧 fence 可以阻止旧结果落库，但无法撤销已经发送给供应商的请求或费用，不能宣称外部 exactly-once。

两节点网络分区时不可能同时保证任意接管和全局严格单执行。选择：**共享付费/自主任务失去协调端后暂停**。
Windows 关机后，Android 可以运行明确分配给它的任务、在已完成交接后接管，或运行独立本机用户任务；不会暗中复制同一共享任务。
未能核对旧节点时的手动接管必须呈现不确定请求并保留旧预算预留。独立聊天一直可用。
未来 NAS 接管需：原协调端停止发租约→排空/核对在途任务→新 epoch 授权→所有仍被信任节点确认（或撤销丢失节点）→新节点恢复任务。
NAS 离线可回到本地聊天；共享高成本工作在确认接管前暂停。

## 9. 故障诊断与重试

| 错误码 | 用户可采取的动作 |
|---|---|
| DISCOVERY_TIMEOUT | 用已知 IP；检查是否同一可互通 LAN |
| LOCAL_NETWORK_PERMISSION | 在系统中允许本地网络访问；拒绝也可离线聊天 |
| PEER_UNREACHABLE | 检查手机 APP 是否运行、网络隔离、休眠与 Windows 专用网络防火墙 |
| PAIR_TOKEN_EXPIRED / MISMATCH | 重新显示二维码；不降低 TLS 验证 |
| PEER_REVOKED / CERT_CHANGED | 用户重新核验并配对；不静默信任新证书 |
| PROFILE_MISMATCH | 进入首配/数据导入流程，不覆盖本地档案 |
| SCHEMA_TOO_NEW | 保留本地数据，升级客户端后重试 |
| EVENT_EQUIVOCATION | 暂停会话，保留摘要与脱敏审计，不应用部分批次 |
| CHECKPOINT_GAP | 重传缺失序号；不能直接跳至最大序号 |
| STORAGE_FULL / INTEGRITY_FAILED | 停止接收写入，释放空间/恢复备份；不提前 ACK |

网络重试指数退避加随机抖动并设上限；前台网络恢复、主动打开 APP 和可信设备可达事件可重置退避。
显示 last_successful_sync、last_attempt、错误码及待传数，不把连接成功当作全部数据完成。
对远端活动显示最后**本地接收**时间与离线/过期标签；不能用远端设备未来时间戳证明它仍在线。
