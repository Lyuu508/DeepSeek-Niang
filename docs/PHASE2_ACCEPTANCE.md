# 独立测试包的真实双端验收入口

最新手机修订仅保留电脑“连接手机”弹出码、手机“扫一扫”实时连接。本机信息应在页面最底部，手动同步保留。旧安装包仍在发布页，不能当作新代码验收；相同测试签名到位且实际新 APK 验签/覆盖条件通过后，才可替换下载。新增实机项目：通知栏/刘海不遮标题，导航栏与键盘不遮输入，底部四项导航可用，扫码后镜头释放，两端自动同步以及断线后手动重试。保持原聊天/人格/记忆，勿卸载清数据。

当前中文 Windows 修订与旧手机 APK 分别使用独立构建报告；这是用户选择等待相同 Android 签名后的单端修订，不能按下文未来完整新版本的同源条件将它们标记为同源。已发布手机 APK 暂未包含一键扫码：请在电脑选择“旧版手机：显示兼容配对码”，使用既有双方确认步骤。新扫码代码仅完成自动化/编译检查，手机交付前不要把家庭扫码验收勾选通过。

本节为最新阶段 2 测试交付要求；下文“升级前”仍只适用于未来的原签名正式升级包。当前 `.test` APK 必须与 v0.0.1 并存，不能用它覆盖原应用。不要卸载正式应用、清理旧数据库或复制活动中的 WAL 文件。安装前核对测试包 SHA256SUMS、applicationId=io.local.deepseekcompanion.test、0.0.2/1002 和测试启动名称；开发签名有效不代表原签名升级兼容。

建议 Windows 使用单独测试账户运行 EXE，以合成档案/人格/聊天/记忆进行验收；Android 打开“DeepSeek娘 测试版”。测试应用初始没有旧版数据，正式版应用仍应可独立打开。手动配对会在双方确认后共享资料，故不要把含私人真实聊天的 Windows 资料当作自动化测试夹具。

Windows PC 接路由器网线，Android 接同一路由器的普通 Wi-Fi，先核对发现、一次性码、两端证书指纹与双方确认，再按下文进行双向聊天、记忆、并发字段、删除、断网/进程重启/地址变化与撤销验收。保留双方设备/OS、两个包的源码 SHA/哈希、操作与观察；不上传二维码、私钥、API Key、数据库或聊天正文。

当前云主机没有可用的 Windows/Android 物理设备组合，此清单未实际执行；Loopback TLS、UI Mock、Hosted Windows 安装 smoke 和 APK 编译不能替代本节验收。

# 阶段 2 安装与家庭局域网验收

本文件是实机操作步骤，不是已通过的实机报告。目标版本 0.0.2，Windows 10/11 x64、Android 10+ ARM64。
发布前必须有同 SHA 的 EXE、APK、SHA256SUMS.txt 和 BUILD-RESULTS.json；若报告未发布或签名未解决，不使用旧包冒充。

## 升级前

保留现有数据，不卸载、不清除应用数据。Android 必须与 v0.0.1 的真实签名 SHA-256 `9de96ea5fb1d0b3f91ea73d9a16c030428453b15838927a85f86773eaef208a1` 相同，applicationId 仍是 `io.local.deepseekcompanion`，versionCode 为 1002。指纹不符停止升级。EXE 暂无 Authenticode 签名。
核对下载文件哈希、BUILD-RESULTS 中两个 source_commit 相同且对应 Tag。应用首次打开旧 v1/v2/v3 数据库前执行 SQLite Online Backup；`.pre-v4-UUID.bak` 是包含私密数据的本地一致备份，不能上传 GitHub。

## 首配

1. PC 通过网线、手机通过同一路由器 Wi-Fi，使用普通家庭网络，不使用访客隔离网络。两端打开应用，各自在“局域网同步”启用。
2. Windows 仅允许本应用访问专用网络，不关闭防火墙或杀毒软件，不配置公网端口转发。
3. 一端显示二维码，另一端拍摄/选择二维码图片或粘贴完整一次性码，选择发现的地址；发现失败时填写对端 IPv4 与页面显示的随机监听端口。界面不扫描网段。
4. 两端核对对方页面“本机证书 SHA-256”与本端待配对指纹，双方勾选数据共享确认再点击确认。码 120 秒过期，5 次错误即失效；关闭配对页面会取消待配对。
5. 已有两个独立档案时保留两端所有人格 UUID，不自动把同名默认人格合并或覆盖。双方都应看到相同的人格集合。每个人格的主空间 UUID 保持一致。

## 双向与离线

- 在 PC 的人格 A 发中文消息、新建人格 B，在手机分别查看 A/B；手机回复后 PC 可见。模型 Key 各设备单独配置，不通过同步传输。
- 在两端离线分别修改同一人格的不同偏好，恢复网络后应合并；并发修改同一字段应稳定选主，并在“保留的并发修订”看到候选。可重新编辑需要保留的值。
- 同一条记忆重复同步十次不应重复创建。PC 删除记忆、手机离线编辑该记忆后重连，该 ID 不能复活；恢复内容应新建记忆。
- 关闭 PC，手机继续聊天和写记忆；重新打开 PC 后自动补传。关闭手机 Wi-Fi、恢复 Wi-Fi、改变 PC DHCP 地址，再检查自动发现或手动回连。
- 保留重生成变体、消息时间、原 UUID、每个人格独立记忆与用量。正在生成的草稿在本机保留，只有最终/中断/失败记录同步，不让两端代替彼此重新请求模型。
- 观察连接、身份验证、同步、成功、错误与等待重连状态。待发计数包括全部事件；未收齐、未事务提交或还有待发内容时不能按成功验收。
- 解除配对后对端立即失去本机同步权限；已同步的历史保留在各自数据库，不承诺远程擦除。重新信任必须再次人工配对。

## 故障与范围

mDNS/NSD 地址仅是未验证候选，不能凭设备名称授权。访客网络/AP 隔离/VLAN 可使发现和 IP 连接都失败；同一 SSID 并不证明可互通。当前使用 RFC1918 IPv4；不支持公网、DNS 名称或 IPv6 手动地址。
Android 前台同步，系统暂停或强制停止后不保证实时后台连接；打开应用恢复网络后补传。当前同步针对直接配对的来源，不为未经配对的第三设备转发签名授权；多个设备需分别直接配对。
关系/生活/任务的原型数据与证据可同步，不启动阶段 3～9 的自主引擎。远端任务记录不授予本机执行租约。

记录设备/OS、两包哈希、源 SHA、测试人格 ID、操作与观察。不要上传真实 Key、数据库、聊天、私钥或二维码。自动化双设备测试不等于家庭网线 PC + Wi-Fi 手机验收。
