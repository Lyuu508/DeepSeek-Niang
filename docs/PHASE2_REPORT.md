## 已实现的代码

- `companion-sync`：显式启用的私有 IPv4 LAN 监听、Windows mDNS、Android 私有原生 NSD 桥、网络切换后发现、已知 IP:端口回退、可信设备、自动重试和手动重连。不要求 PC 使用 Wi-Fi；不扫描网段、不增加云数据库或中转服务。
- 二维码/完整一次性配对码：256 位随机 token、120 秒、5 次失败上限、双方人工核对指纹与确认、退出取消。服务端保存 token 摘要；证书/事件公钥共同绑定上下文，客户端分别证明 TLS P-256 私钥和 Ed25519 私钥持有能力。二维码没有长期私钥。
- 首配通过固定服务端证书的 TLS 1.3 引导；后续同步必须通过双方证书验证与应用层已授权/未撤销检查。ECDSA/TLS 使用 ring/rustls，原始来源事件使用 Ed25519 + RFC 8785 JCS。陌生来源、坏签名、序号缺口、同 ID 不同正文、无证书与撤销身份拒绝，失败批次不 ACK。
- SQLite v4：事务内待发队列、独立生产日志、连续游标、64 条且有字节上限的分页、双向提交后确认、重试/重启补传、字段逻辑寄存器、冲突副本、永久删除标记与 FTS 清理。实验 `import_lab_batch` 不接入生产网络。
- 首配保留两端独立档案、人格 UUID、永久空间和原始行；显式授权的共享档案可在两端继续离线聊天。两端同名默认人格不自动覆盖。已存在实体不因更新/切换设备重新生成 UUID。消息按逻辑时钟与稳定来源键排序，保留显示时间；设备墙钟不裁决冲突。
- 同步投影包括人格/设定、永久空间映射、全部已完成/中断/失败消息及回复变体、记忆/关联、删除标记、原始关系证据与重算状态、虚拟生活状态/计划/活动、任务记录/检查点、用量和白名单共享偏好。正在生成的临时草稿与本机选择不传输；远端活动是历史快照，不冒充在线租约。
- 不同步 API Key、TLS/签名私钥、账号登录凭据、任意设备设置、执行 lease_boot_id/期限/owner/fence。Windows 使用独立 Credential Manager 槽，Android 使用 Keystore AES-GCM 加密私有文件。已有配对但本机密钥缺失时失败关闭，不冒用原身份自动换钥。
- 独立同步页：设备/指纹/最近成功/双向状态/待发事件/进度/错误/重连/撤销/冲突修订、配对二维码图片识别与明确的隔离网络提示。旧聊天、人格切换和 Key 管理保持可用。阶段 3～9 自主引擎没有启用。

## 构建与发布流程

CI 与 Release 分离。`ci.yml` 测试并调用双平台构建；Windows 复用受检脚本与托管安装启动 smoke；Android CI 仅构建未签名检查包。`release.yml` 只在阶段授权后手动运行，固定完整 main SHA，双端与测试全成功后才由写权限 job 集合校验、上传草稿并公开 Pre-release。Artifacts 按 run_attempt 保留 30 天；失败重试不抹掉旧诊断。

正式 Release 附件为 EXE、同 SHA 且匹配原签名的 APK、SHA256SUMS、BUILD-RESULTS、变更记录与安装验收说明。公开后实际下载全部附件再验证哈希。历史 Tag/Release 不覆盖；仅可清理本次操作明确创建且尚未公开的失败草稿。没有依据包 PID/文件名或普通源码 ZIP 宣称构建成功。
