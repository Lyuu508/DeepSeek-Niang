# schema7 → schema8 数据迁移

旧迁移0001–0007字节不变。SQLite 在线一致性备份包含已提交 WAL，路径形如 `companion.pre-v8-UUID.bak`，然后在私有连接上执行一个 IMMEDIATE 事务；中途失败不提交。验证既有消息/记忆/事件/任务/人格/设备/配对/生活记录行数、FK 和资料归属，再恢复外键执行。坏迁移测试确认 user_version 保持7，旧表结构与 UUID 不变，备份仍可用。

扩展原表：

- `task_queue.authority_epoch`：仅本机权威使用，重启递增，不复制实时租约/fence/epoch。
- `life_plans`：主机、状态、创建/下次时间，原 JSON 记录步骤及持续时长；旧行保留，空主机代表旧原型。
- `companion_activities`：保留 ID，扩展活动/任务状态、task/plan 外键、累计时长、已提交进度和检查点序号。
- `companion_life_events`：扩展恢复/取消/失败状态和同一任务的序号，原事件 ID 和默认0保留。
- `companion_memory_meta`：允许 `life` 来源并关联完成事件，不修改原记忆事件/修订。
- `budget_reservations`：创建时间，继续作为本地预留账本；未知执行保留预算。
- 新增 `companion_receipts` 是既有主动消息的每设备回执子表，分别保存阅读与通知状态，没有重复消息系统。

`companion_presence` 只保存本机窗口是否聚焦与采样时间，不参与同步或执行授权。

日记直接使用现有事件视图，兴趣继续使用 character_interests，计划继续使用 life_plans，没有重新生成人格或覆盖数据库。生命活动和完成记忆参与现有签名复制；已读回执只能由其 device_id 本人签名，生活成果只能由绑定主机签名。

升级后排队的旧签名事件保持原始 wire/签名，只在应用到 SQLite 时补上已知的新列默认值；不接受任意缺失/额外列，不重新签署旧来源。lease/epoch 不从同步数据获得执行授权。生产协议要求双方 schema 一致，因此请同时更新电脑和手机到 v0.0.5，旧版本混用会报告版本不兼容，而不是默默失败。

恢复时应先关闭应用并保存当前库及备份副本，使用经过核对的对应 schema 文件恢复整个一致性备份，不在开启 WAL 的运行进程中直接覆盖数据库。设备同步不能代替独立备份。APK 沿用原 .test2 应用身份和数据目录，不需要卸载/清数据。
