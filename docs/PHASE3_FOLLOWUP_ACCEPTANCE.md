# 阶段 3 修复候选：安装与实机验收

此清单目前未执行真实设备验收。候选0.0.4/1004仍待确认版本后公开；只有拿到本次同一源码的 EXE 和 APK 才能验收，不能一端仍运行旧安装包。

1. 电脑完全退出旧进程，保留旧数据后安装新中文 EXE；手机保留“DeepSeek娘 扫码测试版”并覆盖安装同签名1004 APK，不卸载、不清数据。原 v0.0.1/早期 `.test` 独立安装保持，不可跨 applicationId 覆盖。先确认两端设置显示同一候选版本。
2. 电脑使用同一路由器下网线或 Wi-Fi；手机用该路由器普通 Wi-Fi，前台打开。Windows 为此应用允许专用网络访问，不关闭整个防火墙，不开路由器公网映射。访客网络/客户端隔离需要路由器管理员处理。
3. 电脑设置保存自己的 DeepSeek API Key。打开“设备连接”点击“连接手机”，只向自己的手机展示临时二维码。手机点击“扫一扫”授权相机后扫描。无需手填码/IP。
4. 等待“同步完成”和手机“已配置”Key状态。检查两端默认人格只有一个、persona_id/头像/名称/人设一致；原手机聊天和记忆仍存在，手动创建的人格仍独立。再次扫码不得再多出人格。不要把真实 API Key、二维码或数据库发到公开 issue。
5. 用不同合成文本分别从手机、电脑发送消息，检查对方实际能看到，待发数回零。按“手动同步”也应成功。暂时断手机 Wi-Fi 后两端各聊几句，恢复前台网络后增量补传，无重复/丢失。再验收电脑关机/重启、手机锁屏/重开；后台限制可能延迟，不宣称应用被杀仍能实时同步。
6. 如失败，展开连接详情，记录固定错误代码、两端版本、是否首次同步/待发数；区分网络不可达、版本不同、证书错误、旧数据投影失败、安全存储失败。不要删除应用或数据以“解决”失败。可分享非敏感错误码，勿分享私钥/Key/完整数据库。
7. 手机直接发一条真实聊天，验证扫描复制的Key可用；不必手抄Key。电脑没有Key时重扫应保留手机已有Key。明确重扫有Key的电脑会更新手机Key，普通自动同步不更新。解除连接后如要撤销Key使用，还要在手机删除并到提供商轮换。
8. 聊30轮以上再提旧话题，带上先前的人物/地点等关键词，检查旧聊片段是否命中；把重要事实设为重要记忆，再验证召回。编辑/删除一条记忆后不应从旧聊重新发送其原事实。分别关闭记忆/聊天历史验证隐私控制。
9. 电脑检查图三布局：顶部横栏、左侧实际人格、中央永久聊天、右侧实时关系/情绪/生活与设置；仅从人格管理新建后左侧多卡片。右侧切换设置、保存最近6轮预设应生效，聊天仍留在中央。手机系统栏、键盘与底部导航不互相遮挡。
10. 对照提供商真实 usage 和应用每日分类统计，不用字节预算冒充精确Token。生活/主动消息默认关闭，开启后验收频率/安静时段/重启去重，不把虚拟活动当真实媒体观看。

自动化已覆盖的合成数据库、真实回环TLS与UI夹具见同源 BUILD-RESULTS / AUTOMATED-TEST-RESULTS；这些不能替代上述主人设备检查。验收失败保留迁移前一致备份和当前库，先排查并保护升级后的新聊天，不擅自回退覆盖或合并手动人格。
