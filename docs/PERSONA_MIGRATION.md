# v3 人格与永久时间线迁移

适用本地版本 0.1.0-dev.2。保留 0001_initial.sql / 0002_chat.sql 原字节，仅新增 0003_personas.sql。当前环境未发现用户业务库，以下结果来自真实 SQLite 文件的明确测试夹具。

## 身份与结构

profile_id 是配对档案/数据集，device_id 是本机身份，persona_id 才是可切换人格。Credential Manager target、Keystore alias/AAD、应用目录都沿用原 profile/identifier。Key 为本设备共享凭据，不成为人格设定或同步数据。

| 新表 | 约束及用途 |
|---|---|
| personas | 独立 UUID、profile、名称、唯一 main_conversation_id、默认标记及版本 |
| conversation_personas | 一个原会话只属于一个人格，归属不可修改，标记旧归档 |
| persona_chat_preferences | 独立人设、称呼、模型/近期上下文/生成偏好 |
| persona_states | 独立关系/情绪/生活/兴趣容器，初始未评估/未知/未启动 |
| persona_selection | 每本地设备上次选择，不跨设备复制 |

十三张旧表增加 persona_id 与索引/触发器：memories、relationship_events、character_moods、character_interests、life_plans、daily_activities、life_events、proactive_messages、video_sources、meme_knowledge、task_queue、activity_states、api_usage_records。默认人格 ID 等于原 profile_id，已有行保留原档案归属；owner 分配后不可改变，记忆关系不跨人格。

关系/生活等自动引擎没有启用。阶段0原型的 profile 级表仍保留并兼容默认人格；未来上线须扩展原型唯一键、事件及 Task API，不能把加列当作已完成多人格自主生活。

## 升级事务

1. 原路径取得进程文件锁，开启外键、WAL、FULL synchronous，检查 user_version 及已执行迁移哈希；高版本/旧迁移被篡改时拒绝写入。
2. v1/v2 文件以 SQLite Online Backup 写同目录 `companion.pre-v3-<UUID>.bak`（以原文件替换扩展名生成）。包含已提交 WAL，备份失败不开始 DDL；内存测试不产生备份。
3. 所有待执行迁移放进同一 Immediate 事务。每个旧 profile 建默认人格/主空间，映射原会话；复制旧人设与称呼，旧默认名字规范成 DeepSeek娘，保留自定义名称。
4. 消息、原会话、请求/回复变体、用量、原同步信封/序号/哈希、检查点、墓碑、任务检查点都不重写或删除。旧关系状态只标记 legacy_prototype，不伪造已运行引擎。
5. 提交前验证消息/事件/记忆/用量/任务行数、消息与会话跨档案归属及外键。失败整体回滚，user_version 保持原值，留下备份；成功写入迁移哈希及版本3。
6. 再次打开不重复插入人格或消息、不重复升级备份，恢复上次人格；旧处理中请求沿用阶段1明确中断恢复。

业务库和自动 `.bak` 当前未做库级加密，属于私密副本，不进源码/GitHub；这不是后续计划中的加密历史备份。

## 时间线、上下文和运行中切换

旧 conversation 原始行保留，由映射读为一个主空间视图。按原 created_at_ms 排列，同时间用因果 Lamport/角色/UUID 稳定排序，缺时间显示“早期记录”；这些时间不用于同步冲突判定。DTO 使用主空间 ID，物理消息仍留在原会话，原 UUID/内容/时间/角色/状态不变。

新消息只写主空间。原生 IPC 不再提供创建/改名旧会话入口，只允许主空间开始聊天和读取；内部 legacy API 为旧测试/导入适配保留。重生成可以引用旧归档的最后一轮用户消息，用户回合不重复，旧回复变体仍可查看。

上下文仅含请求所属人格的有限近期回合。Service 从请求会话读取设置，完成用量也按会话归属保存；切换对象不会迁移正在生成的回复。UI 按主空间缓存消息/输入，并保护流式事件不被晚到的旧历史快照覆盖。

## 实际测试

九项新增 Rust 测试覆盖：文件重启后上次人格/身份保留；设置、上下文、记忆关键词/FTS、状态和用量隔离；生成中切换；跨人格记忆修改/删除拒绝；旧v2两会话升级备份与时间线；旧回合重生成；跨档案坏库整事务回滚；改名保持主空间；直接SQL归属/记忆关联保护。原48项仍通过，总57项。

旧库夹具只有合成文本，不是用户数据。用户设备仍需保留备份后做覆盖升级/重启验收，不能据此声称已迁移真实手机或电脑。

## 回滚与恢复

迁移失败自动回滚，先保留脱敏错误与 `.bak`，不要删库。高版本或坏库不会被自动覆盖。

回到 dev.1 必须完全关闭 app/后台，另存当前 v3 一致备份，再用迁移前 v2 `.bak` 恢复到原私有位置。当前库已保全且进程已停后移开原 `-wal`/`-shm`，不能和恢复主库混用；保留原始备份，检查完整性/外键/版本后再启动旧版。只能回到备份时状态，不包含 v3 后新消息。不能直接让旧版打开v3，或修改 user_version 假装兼容。

Android 私有目录不可随意通过文件管理器替换，需用户授权开发工具或后续恢复 UI；不建议卸载清数据。本次无一键降级/跨设备回滚。未来同步启用后，历史恢复需新导入事件，不回退身份/检查点冒用旧事件流。
