# v0.1.2 聊天、记忆与自主回忆

## 使用

- 在聊天中选择一条自己的消息，点击「收录共同回忆」。在「本地数据 → 共同回忆」搜索、收藏或跳转到原消息。可编辑同一条资料并授权相关聊天引用。
- 在「本地数据 → 长期记忆」管理来源、重要性和状态。记录为事件后可填预计完成时间。完成、停用、纠正或删除后，后续筛选会读取最新状态。
- 如需旧话题主动回忆，先在「关系与日常」开启主动分享及模型生成，再在选中的记忆上勾选「允许与当前话题相关时用于 DeepSeek 聊天」和「允许这条记忆用于主动回忆」。事件的定向提醒另有授权。修改安静时段、频率和每日预算仍从原来的设置入口进行。
- 在「关系与日常」可调整虚拟兴趣权重。权重为零会排除该兴趣，恢复自动会使用既有活动历史推导的权重。

## 数据、检索与上下文

近期消息使用有界的 SQLite 查询，按已同步的逻辑顺序读取。与当前话题相关的历史片段提供带来源的简短摘录。长会话通过本地检索逐次查找有关资料。语义向量服务和长期滚动摘要尚未接入。

新事件和共同回忆继续以原记忆 ID 和来源消息 ID 串联。事件时间按设备提供的时区解释，日期规则覆盖常用中文相对日期。对于不能可靠解析的时间可手动填写。明确纠正关联相同主题，历史记录继续可见，检索优先选取有效信息；歧义保留待确认候选。最近引用时间保存在本机。

模型收到人设与风格、当前对话、设备时间、允许的记忆、关系和虚拟状态。外部观测与插件数据按来源进入。复杂问题按模型能力开启推理；其他聊天仍走一次 DeepSeek 流式生成。默认不会读取屏幕或设备使用情况。

短时间连续发送可合并最多三条文本。短句按显式分隔标记渲染为多个可复制、可朗读的气泡，整组使用现有消息、生成和同步 ID。代码块、表格与复杂内容保持完整。输入被归组后交给原有的持久化入口。

## 自主回忆与同步

本地候选筛选重用主动分享的单一 Windows 主机、任务租约和消息台账。它会检查候选年龄、来源、未完成状态、安静时段、频率、情绪与用户最近的发言，再按重要性和时间挑选。已参与决定的同条记忆不会重复触发，相同主题受时间窗限制。5～20 秒延迟结束时重算资格，模型决定是否发送及表达意图，提交前再验证记忆版本和权限。

打包在同一次申请中的短气泡保持同一回复身份。生成费用只在真实调用时产生，只记录服务实际返回的用量；主动回忆在现有日常消耗统计中有独立分类。普通聊天最多三条短输入可以共用一次请求。实际输入 Token、输出 Token 和模型延迟需要真实账户测量。

沿用局域网的认证、加密和签名日志。共同回忆、事件状态、兴趣权重、发送记录及删除标记随原有身份同步。设备时区和最近引用时间留在本机。两台设备都升级后使用新字段与事件。Android 可独立聊天和查看同步结果，后台自主回忆由选定的 Windows 主机执行。

迁移事务保留原人格 UUID、聊天 ID、记忆和分享记录。做数据验收时可先在本地数据页核对备份和完整性，再用两台设备检查覆盖升级、离线修改、删除和重新同步。

## 验证

自动化覆盖短回复渲染、话题检索、作息纠正、来源查看、跨人格隔离、回忆撤回、预算和加密同步。浏览器夹具用于展示界面并触发真实前端代码。服务端响应夹具、SQLite 迁移、TLS 连接、原生安装和实机测试分别记录。基于官方 [DeepSeek 官方模型资料](https://api-docs.deepseek.com/) 构造请求，真实聊天质量与 Token 对照仍须授权凭据验证。

### Android 签名交接

正式身份 `io.local.deepseekcompanion` 绑定原证书 SHA-256 `9de96ea5fb1d0b3f91ea73d9a16c030428453b15838927a85f86773eaef208a1`。v0.1.1 的 `.acceptance` 安装包有独立包名及证书。保留验收包数据时继续使用对应验收身份，或使用现有配对与备份能力保留可迁移的数据。

仓库所有者或获授权管理员可在 Actions Secrets 保存原正式密钥和密码。设置名称为 `ANDROID_KEYSTORE_B64`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。将 Base64 直接输送给 GitHub Secrets CLI，并通过交互输入密码，避免把私密值传给命令参数、日志、仓库文件或聊天。安装包验签报告可以公开，密钥应保管在受控的原存放位置和安全备份中。[仓库 Actions Secrets](https://github.com/Lyuu508/DeepSeek-Niang/settings/secrets/actions)

其他账号由仓库所有者赋予相应权限后可以触发「Authorized native release」，提供最新经测试的 main 提交 SHA 和已授权版本，勾选正式发布。Actions 在临时文件中完成签名和清理，流程核对原公开 APK、当前证书、同源构建和模拟器升级。使用 `build_only` 可以获得等待签名的正式身份候选，适用于暂时无法配置 Secrets 的发布过程。
